# Authentication Methods in Windows Domains

# Overview

* Windows domains use authentication protocols to verify user credentials.
* Credentials are stored on:

```text
Domain Controllers (DCs)
```

* Two main authentication protocols:

  * Kerberos
  * NetNTLM

---

# Authentication Protocols

| Protocol | Description |
|---|---|
| Kerberos | Modern default authentication protocol |
| NetNTLM | Legacy authentication protocol |

---

# Kerberos Authentication

## Overview

* Default authentication protocol in modern Windows domains.
* Uses:

  * Tickets
  * Session keys
  * Trusted authentication

---

# Key Components

## KDC (Key Distribution Center)

* Runs on Domain Controller
* Responsible for:

  * Authenticating users
  * Creating Kerberos tickets

---

## TGT (Ticket Granting Ticket)

* Proof that user authenticated successfully
* Allows requesting more tickets without re-entering password

---

## TGS (Ticket Granting Service)

* Ticket for accessing a specific service

Examples:

* File shares
* Websites
* Databases

---

## SPN (Service Principal Name)

Identifies:

* Service name
* Server hosting service

---

# Kerberos Authentication Process

# Step 1 — Initial Authentication

## User Sends

* Username
* Timestamp encrypted using key derived from password

To:

```text
KDC
```

---

## KDC Responds With

* TGT (Ticket Granting Ticket)
* Session Key

---

## Important Notes

### TGT Encryption

* Encrypted with:

```text
krbtgt account password hash
```

### Session Key

* Used for future ticket requests
* Stored inside encrypted TGT

---

# Step 2 — Requesting Service Ticket (TGS)

When user wants to access a service:

Examples:

* Shared folder
* Website
* Database

---

## User Sends

* Username
* Encrypted timestamp
* TGT
* SPN

To:

```text
KDC
```

---

## KDC Returns

* TGS
* Service Session Key

---

## TGS Encryption

Encrypted using:

```text
Service Owner Hash
```

Service Owner:

* User account
* Machine account running service

---

# Step 3 — Accessing Service

## User Sends

```text
TGS
```

to target service.

---

## Service Actions

* Decrypts TGS
* Verifies Service Session Key
* Grants access if valid

---

# Important Kerberos Concepts

## Tickets

Used as proof of authentication.

---

## Session Keys

Used for secure communication between:

* User
* KDC
* Services

---

## Password Security

* User password is not repeatedly sent over network.

---

# NetNTLM Authentication

# Overview

* Legacy authentication protocol
* Uses:

```text
Challenge-Response Authentication
```

---

# NetNTLM Authentication Process

# Step 1 — Authentication Request

Client requests access to server.

---

# Step 2 — Server Sends Challenge

* Server generates random number
* Sends challenge to client

---

# Step 3 — Client Creates Response

Client combines:

* NTLM password hash
* Server challenge
* Other known data

To generate:

```text
Authentication Response
```

---

# Step 4 — Server Contacts Domain Controller

Server forwards:

* Challenge
* Client response

To:

```text
Domain Controller
```

---

# Step 5 — Verification

Domain Controller:

* Recalculates expected response
* Compares with client response

---

## If Responses Match

```text
Authentication successful
```

---

## If Responses Don't Match

```text
Access denied
```

---

# Step 6 — Authentication Result Returned

* Domain Controller → Server
* Server → Client

---

# Important NetNTLM Notes

## Password Safety

* Password is never sent over network
* NTLM hash is used instead

---

## Local Account Authentication

If local account is used:

* Server verifies authentication itself
* No Domain Controller needed

Reason:

* Password hash exists in local:

```text
SAM database
```

---

# Kerberos vs NetNTLM

| Feature | Kerberos | NetNTLM |
|---|---|---|
| Default in modern Windows | Yes | No |
| Uses tickets | Yes | No |
| Uses challenge-response | No | Yes |
| More secure | Yes | Less secure |
| Legacy protocol | No | Yes |
| Requires KDC | Yes | Uses DC for verification |

---

# Key Security Concepts

## Kerberos

* Ticket-based authentication
* More secure
* Faster repeated authentication
* Default modern protocol

---

## NetNTLM

* Older protocol
* Challenge-response based
* Kept for compatibility

---

# Key Points

* Windows domains mainly use:

  * Kerberos
  * NetNTLM

* Kerberos uses:

  * TGT
  * TGS
  * Session Keys

* NetNTLM uses:

  * Challenge-response mechanism

* Credentials are validated through:

```text
Domain Controller
```

* Passwords are not directly transmitted over the network.
