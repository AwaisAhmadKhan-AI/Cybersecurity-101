# Trees, Forests, and Trusts (Active Directory)

## Why Do We Need Multiple Domains?

A **single domain** works well for small organizations.

As a company grows (new countries, branches, or acquisitions), managing everything in one domain becomes difficult.

Active Directory solves this by using **Trees**, **Forests**, and **Trusts**.

---

# 1. Single Domain

A single domain contains:

- Users
- Computers
- Servers
- One or more Domain Controllers (DCs)

Example:

```text
thm.local
```

Suitable for small organizations.

---

# 2. Tree

A **Tree** is a group of domains that **share the same namespace**.

Example:

```text
thm.local
│
├── uk.thm.local
└── us.thm.local
```

Here:

- `thm.local` is the **Root Domain**.
- `uk.thm.local` and `us.thm.local` are **Subdomains**.

### Why Use a Tree?

Each branch can:

- Have its own Domain Controller.
- Manage its own users and computers.
- Create its own Group Policies (GPOs).
- Be managed independently.

Example:

- UK IT admins manage only **UK resources**.
- US IT admins manage only **US resources**.

This makes administration easier and reduces mistakes.

---

# Enterprise Admins vs Domain Admins

### Domain Admins

- Manage **only their own domain**.
- Example: UK Domain Admins manage only `uk.thm.local`.

### Enterprise Admins

- Manage **every domain** in the tree or forest.
- Have the highest administrative privileges.

---

# 3. Forest

A **Forest** is a collection of **multiple trees with different namespaces**.

Example:

```text
thm.local

mht.local
```

Suppose:

- Company **THM** buys another company **MHT**.
- Each company keeps its own Active Directory.

Together they form one **Forest**.

### Why Use a Forest?

- Different companies or organizations can keep their own domains.
- Each organization manages its own resources independently.
- They can still communicate when needed.

---

# 4. Trust Relationships

A **Trust** allows users from one domain to access resources in another domain.

Without a trust relationship:

- Users from one domain **cannot** access another domain's resources.

---

## One-Way Trust

Example:

```text
AAA trusts BBB
```

Meaning:

- Users from **BBB** can access resources in **AAA** (if permitted).
- Users from **AAA** cannot automatically access BBB.

> **Remember:** The **trust direction** is opposite to the **access direction**.

---

## Two-Way Trust

Both domains trust each other.

```text
AAA ↔ BBB
```

Meaning:

- Users from AAA can access BBB resources (if allowed).
- Users from BBB can access AAA resources (if allowed).

By default, domains in the **same Tree or Forest** have a **two-way trust**.

---

# Important Note

A **Trust** **does NOT** automatically give access to everything.

It only allows administrators to **grant permission** across domains.

Users can access resources **only if they are explicitly authorized**.

---

# Key Points

- **Single Domain** → Best for small organizations.
- **Tree** → Multiple domains sharing the **same namespace**.
- **Forest** → Multiple trees with **different namespaces**.
- **Domain Admins** → Control only their own domain.
- **Enterprise Admins** → Control every domain in the Tree/Forest.
- **Trust** → Allows users from one domain to access another domain's resources.
- **One-Way Trust** → One domain trusts another.
- **Two-Way Trust** → Both domains trust each other.
- Trust **does not automatically grant access**; permissions must still be assigned.
