# Group Policies (GPOs)

# Overview

* Group Policy Objects (GPOs) are collections of settings applied to:

  * Users
  * Computers

* Used to manage:

  * Security settings
  * System configurations
  * Restrictions
  * User environments

* Policies are applied through:

```text
Group Policy Management
```

tool.

---

# Purpose of GPOs

GPOs help administrators:

* Centralize management
* Apply security baselines
* Configure departments differently
* Enforce company rules

Example:

* Restrict Control Panel access
* Force password policies
* Lock inactive systems automatically

---

# How GPOs Work

## Basic Process

1. Create GPO
2. Configure settings
3. Link GPO to an OU/domain
4. Policies apply automatically

---

# GPO Scope

* GPOs apply to:

  * Linked OU
  * All child OUs

Example:

```text
thm.local
└── Sales
```

If a GPO is linked to `thm.local`, it also affects `Sales`.

# Important GPO Sections

## Scope Tab

Shows:

* Where GPO is linked
* Which users/computers receive policy

---

## Security Filtering

Controls who receives the GPO.

Default group:

```text
Authenticated Users
```

Includes:

* All domain users
* All domain computers

---

## Settings Tab

Contains actual configurations.

Two main categories:

### Computer Configuration

Applies to:

* Machines/computers

---

### User Configuration

Applies to:

* User accounts

# SYSVOL

## Purpose

* Stores GPO files
* Used for policy distribution

---

## Default Location

```text
C:\Windows\SYSVOL\sysvol\
```

---

## Important Notes

* All domain users/computers access SYSVOL
* Used to synchronize GPOs

---

# Force GPO Update

Normally updates take time.

To update immediately:

```powershell
gpupdate /force
```

# Task 2 — Auto Lock Screen

## Goal

Automatically lock inactive computers after:

```text
5 minutes
```

---

## Create GPO

### Name

```text
Auto Lock Screen
```

---

## Policy Path

```text
Computer Configuration
→ Policies
→ Windows Settings
→ Security Settings
→ Local Policies
→ Security Options
→ Interactive logon: Machine inactivity limit
```

---

## Configuration

Set inactivity time:

```text
5 minutes
```

---

# Where to Link This GPO

## Best Option

Link to:

```text
thm.local
```

Reason:

* All child OUs inherit policy
* Applies to:

  * Workstations
  * Servers
  * Domain Controllers

---

# Important Note

* User-only OUs ignore Computer Configuration policies.

Example:

* Sales OU contains users only
* Computer policies are ignored there

# Key Points

* GPOs manage users and computers centrally
* Linked GPOs affect child OUs
* Two configuration types:

  * User Configuration
  * Computer Configuration

* SYSVOL distributes GPOs
* `gpupdate /force` refreshes policies manually
* GPOs improve:

  * Security
  * Standardization
  * Administration
