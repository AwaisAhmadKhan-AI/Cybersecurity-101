# TLS (Transport Layer Security)

## What is TLS?

**TLS (Transport Layer Security)** is a cryptographic protocol that provides **secure communication** between a client and a server over an insecure network, such as the Internet.

Its primary goals are to ensure:

- **Confidentiality** – Data cannot be read by unauthorized users.
- **Integrity** – Data cannot be modified during transmission.
- **Authentication** – Verifies the identity of the server (and sometimes the client).

> **Note:** TLS is the modern and secure replacement for **SSL (Secure Sockets Layer)**.

---

# Why Do We Need TLS?

Without TLS:

- Usernames and passwords would be sent as plain text.
- Emails and chat messages could be intercepted.
- Banking and shopping information could be stolen.
- Attackers could modify data while it is being transmitted.

TLS solves these problems by **encrypting communication** between two systems.

---

# A Brief History

| Year | Event |
|------|-------|
| Early 1990s | Need for secure web communication recognized |
| 1995 | SSL 2.0 released by Netscape |
| 1999 | TLS 1.0 introduced by the IETF as an improved version of SSL |
| 2018 | TLS 1.3 released with significant security improvements |

Today, **TLS 1.3** is the latest and most secure version.

---

# OSI Layer

TLS operates at the **Transport Layer (Layer 4)** of the OSI model.

It works together with protocols such as **TCP** to provide secure communication.

---

# What Does TLS Provide?

## 1. Confidentiality

TLS encrypts data so that only the intended sender and receiver can read it.

Example:

Without TLS:

```text
Password = MyPassword123
```

With TLS:

```text
Password = Encrypted Data
```

Anyone capturing the packets will only see encrypted information.

---

## 2. Integrity

TLS ensures that data is **not modified** during transmission.

If an attacker changes even a single bit of data, TLS detects the alteration and rejects the message.

---

## 3. Authentication

TLS uses **digital certificates** to verify that you are communicating with the legitimate server instead of an attacker.

For example, when you visit your bank's website, TLS confirms that it is actually your bank's server.

---

# Protocols That Use TLS

Many common protocols become secure simply by adding TLS.

| Original Protocol | Secure Version | Purpose |
|------------------|---------------|---------|
| HTTP | HTTPS | Secure web browsing |
| DNS | DoT (DNS over TLS) | Secure DNS queries |
| SMTP | SMTPS | Secure email sending |
| POP3 | POP3S | Secure email retrieval |
| IMAP | IMAPS | Secure email synchronization |
| MQTT | MQTTS | Secure IoT messaging |
| SIP | SIPS | Secure VoIP communication |

> The **"S"** in protocols like **HTTPS**, **SMTPS**, and **IMAPS** usually indicates that **TLS** is being used.

# How TLS Works (Simplified)

1. A client requests a secure connection.
2. The server sends its **digital certificate**.
3. The client verifies the certificate.
4. A secure encrypted session is established.
5. All further communication is encrypted.

> The complete TLS handshake is more complex, but these are the basic steps.

---

# Digital Certificates

A **digital certificate** proves the identity of a server (or client).

It contains information such as:

- Domain name
- Public key
- Certificate Authority (CA)
- Expiration date
- Digital signature

When you visit an HTTPS website, your browser checks this certificate before establishing a secure connection.

---

# Certificate Authority (CA)

A **Certificate Authority (CA)** is a trusted organization that verifies identities and issues digital certificates.

Examples include:

- Let's Encrypt
- DigiCert
- Sectigo
- GlobalSign

Your browser already contains a list of trusted Certificate Authorities.

If a certificate is signed by one of these trusted CAs, the browser accepts it automatically.

---

# Certificate Signing Request (CSR)

Before obtaining a certificate, the server administrator creates a **Certificate Signing Request (CSR)**.

The process is:

```text
Create CSR
      │
      ▼
Send CSR to Certificate Authority
      │
      ▼
CA verifies identity
      │
      ▼
CA issues signed TLS certificate
      │
      ▼
Server installs the certificate
```

---

# Let's Encrypt

**Let's Encrypt** is a free Certificate Authority.

It allows website owners to obtain trusted TLS certificates without paying annual fees.

This has greatly increased the adoption of HTTPS across the Internet.

---

# Self-Signed Certificates

A **self-signed certificate** is created and signed by the server itself instead of a trusted Certificate Authority.

### Advantages

- Free
- Easy to create
- Useful for testing and internal networks

### Disadvantages

- Browsers do not trust it by default.
- Users receive security warnings.
- It cannot prove the server's identity.

- Detects data tampering.

- Enables secure online banking, shopping, messaging, and email.

# Quick Revision

- **Full Form:** Transport Layer Security

- **Purpose:** Secure communication over insecure networks
- **Provides:**
  - Confidentiality
  - Integrity
  - Authentication
- **Replaced:** SSL
- **Latest Version:** TLS 1.3
- **Uses:** HTTPS, SMTPS, POP3S, IMAPS, DoT, MQTTS, SIPS

- **Certificate Issued By:** Certificate Authority (CA)
