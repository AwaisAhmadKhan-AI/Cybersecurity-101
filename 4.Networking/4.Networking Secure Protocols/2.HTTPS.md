# HTTPS (Hypertext Transfer Protocol Secure)

## What is HTTPS?

**HTTPS (Hypertext Transfer Protocol Secure)** is the secure version of HTTP.

It combines:

- **HTTP** → Transfers web pages and web data.
- **TLS** → Encrypts and protects the communication.

Simply put:

> **HTTPS = HTTP + TLS**

Unlike HTTP, HTTPS encrypts all communication between the client (browser) and the web server, preventing attackers from reading or modifying the transmitted data.

---

# Default Ports

| Protocol | Default Port | Transport Protocol |
|----------|-------------:|-------------------|
| HTTP | **80** | TCP |
| HTTPS | **443** | TCP + TLS |

---

# Why HTTPS is Needed

HTTP sends data in **plain text**.

This means anyone who intercepts the network traffic can see:

- Usernames
- Passwords
- Cookies
- Credit card information
- Messages
- Downloaded pages

HTTPS solves this problem by encrypting the communication using TLS.

---

# How HTTP Works

Before requesting a webpage, the browser performs these steps:

## Step 1: TCP Connection

The client establishes a **TCP three-way handshake** with the server.

```text
Client
   │ SYN
   ▼
Server
   │ SYN-ACK
   ▼
Client
   │ ACK
```

---

## Step 2: Send HTTP Request

After the TCP connection is established, the browser sends an HTTP request.

Example:

```http
GET / HTTP/1.1
Host: example.com
```

The server processes the request and returns the webpage.

---

## Step 3: Close the Connection

Once communication is complete, the TCP connection is terminated.

---

# HTTP Communication Flow

```text
Browser
   │
   ▼
TCP Handshake
   │
   ▼
HTTP Request
   │
   ▼
HTTP Response
   │
   ▼
TCP Connection Closed
```

Everything in this process is transmitted **without encryption**.

---

# How HTTPS Works

HTTPS adds **TLS encryption** between TCP and HTTP.

The communication now follows these steps:

## Step 1: TCP Three-Way Handshake

The browser establishes a TCP connection with the server.

---

## Step 2: TLS Handshake

The client and server perform a **TLS handshake**.

During this process they:

- Verify the server's identity.
- Exchange encryption information.
- Generate session keys.
- Establish a secure encrypted connection.

---

## Step 3: Secure HTTP Communication

Only after the TLS session is established does the browser send HTTP requests.

Example:

```http
GET / HTTP/1.1
```

Although the request is still normal HTTP, it is now **encrypted by TLS** before being transmitted.

---

# HTTPS Communication Flow

```text
Browser
   │
   ▼
TCP Handshake
   │
   ▼
TLS Handshake
   │
   ▼
Encrypted HTTP Request
   │
   ▼
Encrypted HTTP Response
   │
   ▼
TCP Connection Closed
```

---

# What an Attacker Sees

## HTTP

Anyone capturing packets can read everything.

```text
GET /login

Username: alice
Password: MyPassword123
```

---

## HTTPS

The packets are encrypted.

An attacker only sees unreadable encrypted data.

```text
A7 C3 5D 89 4F 18...
```

Without the encryption keys, the original information cannot be recovered.

---

# Why Wireshark Shows "Application Data"

When capturing HTTPS traffic, Wireshark usually displays:

```text
Application Data
```

instead of:

```text
HTTP GET
```

This is because the HTTP messages are encrypted by TLS.

Without the decryption keys, Wireshark cannot determine the actual application-layer content.

---

# Decrypting HTTPS Traffic

If the TLS session keys are available (for example, during testing), Wireshark can decrypt the traffic.

After decryption, it can display:

- HTTP GET requests
- HTTP responses
- Headers
- Cookies
- Webpage content

Without these keys, the encrypted packets remain unreadable.

---

# Benefits of HTTPS

- Encrypts web traffic.
- Protects usernames and passwords.
- Prevents attackers from reading sensitive information.
- Ensures data integrity.
- Verifies the identity of the web server using digital certificates.
- Enables secure online banking, shopping, email, and messaging.

# HTTP vs HTTPS

| Feature | HTTP | HTTPS |
|----------|------|--------|
| Full Form | Hypertext Transfer Protocol | Hypertext Transfer Protocol Secure |
| Default Port | 80 | 443 |
| Transport | TCP | TCP + TLS |
| Encryption | ❌ No | ✅ Yes |
| Confidentiality | ❌ No | ✅ Yes |
| Integrity Protection | ❌ No | ✅ Yes |
| Authentication | ❌ No | ✅ Yes (Digital Certificates) |
| Safe for Login Pages | ❌ No | ✅ Yes |

---

# Key Point

HTTPS **does not replace HTTP**.

Instead, it **adds TLS** between HTTP and TCP.

```text
HTTP
   │
TLS
   │
TCP
   │
IP
```

This allows HTTP to become secure **without changing how HTTP itself works**.

---

# Quick Revision

- **Full Form:** Hypertext Transfer Protocol Secure
- **Built From:** HTTP + TLS
- **Default Port:** **443**
- **Transport Protocol:** TCP
- **Provides:**
  - Confidentiality
  - Integrity
  - Authentication
- **HTTP Port:** 80
- **HTTPS Port:** 443
- **TLS Handshake:** Occurs after TCP connection and before HTTP communication.
- **Without TLS:** Data is readable.
- **With TLS:** Data is encrypted.

# Interview Tip

Remember the communication order:

```text
HTTP:
TCP Handshake
      ↓
HTTP Communication

HTTPS:
TCP Handshake
      ↓
TLS Handshake
      ↓
Encrypted HTTP Communication
```

> **One-line Summary:** HTTPS is simply **HTTP running over TLS**, providing encrypted and authenticated communication between a client and a web server.
