# SSH (Secure Shell)

**SSH (Secure Shell)** is a secure network protocol used to remotely access and manage another computer over a network.

It was created as a secure replacement for **Telnet**, which sends all communication, including usernames and passwords, in plain text.

SSH encrypts all communication, making remote administration safe even over untrusted networks.

**Default TCP Port:** **22**

---

# Why SSH Was Created

Telnet has one major security weakness:

- All data is transmitted in **plain text**.
- Anyone capturing network traffic can read usernames, passwords, and commands.

SSH solves this problem by encrypting all communication between the client and the server.

---

# History of SSH

- **1995:** SSH-1 was created by **Tatu Ylönen**.
- **1996:** SSH-2 was introduced with improved security.
- **1999:** **OpenSSH**, the most widely used open-source implementation of SSH, was released.

Today, most SSH clients and servers are based on **OpenSSH**.

---

# Key Features of SSH

## 1. Secure Authentication

SSH supports multiple authentication methods:

- Password authentication
- Public key authentication
- Two-factor authentication (2FA)

Public key authentication is more secure because it does not require sending passwords over the network.

---

## 2. Confidentiality

SSH encrypts all transmitted data, preventing attackers from reading network traffic.

It also verifies the server's identity to help protect against **Man-in-the-Middle (MITM)** attacks.

---

## 3. Integrity

SSH ensures that transmitted data is not modified during communication.

If data is altered, the connection can detect the tampering.

---

## 4. SSH Tunneling

SSH can securely forward other network traffic through an encrypted tunnel.

This allows insecure protocols to be used securely and provides functionality similar to a VPN.

---

## 5. X11 Forwarding

SSH can forward graphical applications from a remote Unix/Linux system to your local computer.

This allows you to run GUI applications remotely instead of only using the command line.

Example:

```bash
ssh -X username@hostname
```

The `-X` option enables X11 Forwarding.

---

# Connecting to an SSH Server

General syntax:

```bash
ssh username@hostname
```

Example:

```bash
ssh alice@192.168.1.10
```

If your local username is the same as the remote username, you can simply use:

```bash
ssh hostname
```

After connecting, SSH will request authentication unless public key authentication is already configured.

# Default Ports

| Protocol | Default TCP Port |
|----------|:----------------:|
| Telnet | 23 |
| SSH | 22 |

---

# SSH vs Telnet

| Feature | Telnet | SSH |
|---------|--------|-----|
| Default Port | 23 | 22 |
| Encryption | ❌ No | ✅ Yes |
| Password Protection | ❌ Plain Text | ✅ Encrypted |
| Secure Remote Access | ❌ No | ✅ Yes |
| Recommended Today | ❌ No | ✅ Yes |

---

# Advantages of SSH

- Encrypts all communication.
- Protects usernames and passwords.
- Supports secure authentication methods.
- Prevents eavesdropping.
- Detects data tampering.
- Supports secure tunneling.
- Allows remote command-line and graphical access.

---

# Quick Revision

- **SSH (Secure Shell)** provides **secure remote access** to another computer.
- It is the secure replacement for **Telnet**.
- **Default Port:** **TCP 22**
- Supports **password**, **public key**, and **2FA** authentication.
- Provides:
  - **Confidentiality** (Encryption)
  - **Integrity** (Data protection)
  - **Authentication** (Identity verification)
- Can create **encrypted tunnels** and supports **X11 Forwarding** for running remote graphical applications.
