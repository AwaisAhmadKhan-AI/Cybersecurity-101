# Packet Navigation in Wireshark

Packet navigation features help analysts quickly locate, organize, and investigate packets, especially when working with large capture files containing thousands of packets.

---

# Packet Numbers

Every captured packet is automatically assigned a **unique packet number**.

Example:

```
Packet 1
Packet 2
Packet 3
...
Packet 1500
```

Packet numbers help you:

- Quickly identify packets
- Return to a specific packet later
- Reference packets during analysis
- Follow events in large capture files

---

# Go to Packet

Instead of scrolling through thousands of packets, Wireshark allows you to jump directly to a specific packet.

You can:

- Go to an exact packet number
- Move to the next or previous packet
- Navigate through related packets in a conversation

**Menu:**

```
Go → Go to Packet
```

This is especially useful when documentation or another analyst references a specific packet number.

---

# Find Packets

Wireshark can search packets based on their contents, making it much easier to locate specific events.

**Menu:**

```
Edit → Find Packet
```

---

## Supported Search Types

### 1. Display Filter

Search using Wireshark filter syntax.

Example:

```
http
tcp.port == 80
ip.addr == 192.168.1.10
```

---

### 2. Hex Value

Search for specific hexadecimal bytes.

Example:

```
48 54 54 50
```

---

### 3. String Search

Search for plain text inside packets.

Example:

```
password
login
admin
```

This is one of the most commonly used search methods.

---

### 4. Regular Expression (Regex)

Search using patterns.

Example:

```
user.*
```

Useful for finding text that follows a specific pattern.

---

# Search Locations

Before searching, choose where Wireshark should look.

### Packet List Pane

Searches packet summaries.

Useful for:

- Protocol names
- Source IP
- Destination IP
- Packet info

---

### Packet Details Pane

Searches decoded protocol fields.

Useful for:

- HTTP headers
- TCP flags
- DNS records
- Port numbers

---

### Packet Bytes Pane

Searches raw packet data.

Useful for:

- Hex values
- Raw text
- Binary data

> **Important:** Searching in the wrong pane may return no results even if the data exists elsewhere.

# Mark Packets

Marking packets helps highlight important packets during an investigation.

**Menu:**

```
Edit → Mark Packet
```

or

```
Right Click → Mark Packet
```

Marked packets:

- Appear in **black**
- Stand out from other packets
- Help identify suspicious or important traffic

### Common Uses

- Mark suspicious packets
- Highlight attack traffic
- Save important evidence during analysis

> **Note:** Packet marks are temporary and disappear after the capture file is closed.

---

# Packet Comments

Wireshark allows you to attach notes to individual packets.

Unlike packet marks, **comments are saved with the capture file** until removed.

### Common Uses

- Explain suspicious activity
- Add investigation notes
- Leave comments for teammates
- Document important findings

This is very useful during collaborative investigations.

---

# Export Packets

Large capture files often contain thousands of packets.

Instead of sharing the entire capture, Wireshark lets you export only the packets you need.

**Menu:**

```
File → Export Specified Packets
```

### Benefits

- Share only relevant traffic
- Reduce file size
- Focus investigations on suspicious packets
- Protect unrelated network data

---

# Export Objects (Files)

Wireshark can recover files transferred over certain protocols.

Supported protocols include:

- HTTP
- SMB
- TFTP
- IMF
- DICOM

**Menu:**

```
File → Export Objects
```

Examples of recoverable files:

- Images
- HTML pages
- Documents
- Executables
- PDFs

This feature is commonly used in digital forensics and malware analysis.

---

# Time Display Format

By default, Wireshark displays packet timestamps as:

```
Seconds Since Beginning of Capture
```

You can change how time is displayed.

**Menu:**

```
View → Time Display Format
```

Common formats include:

- Seconds Since Beginning of Capture
- UTC Time
- Local Time
- Date and Time

Changing the time format can make investigations easier, especially when correlating logs from different systems.

---

# Expert Information

Wireshark automatically analyzes captured traffic and flags potential issues.

**Menu:**

```
Analyze → Expert Information
```

or click the Expert Information icon in the status bar.

> **Note:** Expert Information provides suggestions only. It may produce false positives or miss some issues, so analyst verification is always required.

---

# Severity Levels

| Severity | Color | Meaning |
|----------|--------|---------|
| Chat | Blue | Normal protocol activity |
| Note | Cyan | Important but not critical events |
| Warning | Yellow | Possible problems or unusual behavior |
| Error | Red | Serious protocol or packet errors |

---

# Common Expert Information Groups

| Group | Purpose |
|--------|----------|
| Checksum | Detects checksum errors |
| Comment | Shows packets containing comments |
| Malformed | Detects malformed packets |
| Deprecated | Detects deprecated protocol usage |

# Interview Tips

- Every packet captured by Wireshark has a **unique packet number**.
- **Find Packet** supports **Display Filters, Hex, String, and Regex** searches.
- **Packet Marks are temporary**, while **Packet Comments are saved** with the capture file.
- **Export Objects** can recover files transferred over protocols like **HTTP, SMB, and TFTP**.
- **Expert Information** highlights potential issues using four severity levels: **Chat, Note, Warning, and Error**.
- Expert Information assists analysis but **does not replace manual investigation**.
