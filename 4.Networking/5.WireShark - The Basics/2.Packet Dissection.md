# Packet Dissection

Packet dissection (also called **protocol dissection**) is the process of breaking down a network packet into its individual protocol layers and fields so you can understand exactly what data is being transmitted.

Wireshark automatically decodes hundreds of network protocols, making it easier to inspect packet contents. It also allows developers to add support for additional protocols using custom dissectors.

> **Note:** Packet analysis becomes much easier if you already understand the **OSI Model**, since Wireshark organizes packet information according to those layers.

---

# Packet Details Pane

When you select a packet from the **Packet List Pane**, Wireshark displays detailed information about that packet in the **Packet Details Pane**.

Each protocol layer can be expanded to reveal additional information.

Selecting any field also highlights the corresponding bytes in the **Packet Bytes Pane**, making it easy to see exactly where that information is stored inside the packet.

---

# OSI Layers in Wireshark

A typical packet is displayed as multiple protocol layers.

## 1. Frame (Layer 1 - Physical)

The Frame section contains information about the captured packet itself.

It includes details such as:

- Frame number
- Packet size
- Capture time
- Arrival time
- Interface used for capture

**Purpose:** Information about the captured frame, not the network protocol itself.

---

## 2. Ethernet / MAC (Layer 2 - Data Link)

This layer contains the physical hardware addresses used on the local network.

Shows:

- Source MAC Address
- Destination MAC Address
- Ethernet type

Example:

```
Source MAC: 00:1A:2B:3C:4D:5E
Destination MAC: FF:FF:FF:FF:FF:FF
```

**Purpose:** Identifies devices on the local network.

---

## 3. IP (Layer 3 - Network)

This layer contains logical addressing information.

Shows:

- Source IP Address
- Destination IP Address
- TTL
- IP Version
- Header Length
- Fragmentation information

Example:

```
Source IP: 192.168.1.10
Destination IP: 142.250.190.78
```

**Purpose:** Routes packets between different networks.

---

## 4. Transport Layer (TCP / UDP)

This layer shows transport protocol information.

### TCP

Displays:

- Source Port
- Destination Port
- Sequence Number
- Acknowledgment Number
- Window Size
- TCP Flags (SYN, ACK, FIN, etc.)

### UDP

Displays:

- Source Port
- Destination Port
- Datagram Length
- Checksum

Example:

```
Source Port: 53210
Destination Port: 443
```

**Purpose:** Enables communication between applications using port numbers.

---

## 5. TCP Reassembly / Protocol Errors

Sometimes data is too large for one TCP packet.

Wireshark automatically:

- Reassembles fragmented TCP segments
- Detects retransmissions
- Detects duplicate packets
- Detects missing segments
- Displays protocol errors when necessary

This helps reconstruct the complete application data.

---

## 6. Application Layer

This layer depends on the protocol being used.

Examples include:

- HTTP
- HTTPS
- FTP
- DNS
- SMTP
- SSH
- SMB
- POP3
- IMAP

For HTTP packets, Wireshark may display:

```
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Firefox
```

For DNS packets:

```
Query:
example.com
Type: A
```

**Purpose:** Shows protocol-specific information.

---

## 7. Application Data

This section contains the actual payload exchanged between applications.

Examples:

- HTML pages
- Images
- Email contents
- Chat messages
- File contents
- JSON data
- API responses

If encryption (TLS/HTTPS) is used, this data appears encrypted unless Wireshark has the decryption keys.

---

# Packet Bytes Pane

The Packet Bytes Pane displays the raw packet data.

It contains two representations:

- **Hexadecimal values** (machine-readable)
- **ASCII text** (human-readable when possible)

When you click a field in the Packet Details Pane, Wireshark highlights the corresponding bytes in this pane.

This helps correlate protocol fields with the raw packet data.

---

# Why Packet Dissection is Useful

Packet dissection helps you:

- Understand how network protocols work
- Analyze packet contents layer by layer
- Troubleshoot network communication issues
- Detect malformed or suspicious packets
- Investigate network attacks
- Learn protocol structures
- Verify application behavior

# Quick Summary

| Layer | Wireshark Shows | Example Information |
|--------|-----------------|---------------------|
| Frame | Capture details | Time, frame number, packet size |
| Layer 2 | Ethernet (MAC) | Source/Destination MAC |
| Layer 3 | IP | Source/Destination IP |
| Layer 4 | TCP/UDP | Ports, flags, sequence numbers |
| TCP Analysis | Reassembly & errors | Retransmissions, missing packets |
| Application | Protocol details | HTTP, FTP, DNS, SMTP, SSH |
| Application Data | Actual payload | HTML, email, files, JSON |

---

# Interview Tips

- Packet dissection means **breaking a network packet into protocol layers for detailed analysis**.
- Wireshark organizes packet information according to the **OSI model**.
- Clicking a field in the Packet Details Pane highlights its raw bytes in the Packet Bytes Pane.
- The Application Layer shows protocol-specific data such as HTTP, DNS, FTP, SMTP, or SSH.
- The Packet Bytes Pane displays both **hexadecimal** and **ASCII** representations of the packet.
