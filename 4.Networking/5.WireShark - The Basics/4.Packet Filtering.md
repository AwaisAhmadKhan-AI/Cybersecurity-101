# Packet Filtering in Wireshark

Packet filtering is one of Wireshark's most powerful features. It allows you to remove unnecessary traffic (noise) and focus only on the packets relevant to your investigation.

Wireshark supports **two types of filters**:

- **Capture Filters** – Filter packets **before they are captured**.
- **Display Filters** – Filter packets **after they have been captured**.

> **Note:** Display filters do **not** delete packets. They only hide packets that do not match the filter.

---

# Capture Filters vs Display Filters

| Capture Filter | Display Filter |
|---------------|----------------|
| Applied before packet capture | Applied after packet capture |
| Captures only matching packets | Shows only matching packets |
| Cannot display hidden packets later | Hidden packets can be shown again by removing the filter |
| Used to reduce capture size | Used during packet analysis |

---

# Display Filters

Display filters are the most commonly used filters during investigations.

They help analysts:

- Focus on specific protocols
- Find specific IP addresses
- Analyze conversations
- Hide unrelated traffic
- Speed up investigations

Filters are entered into the **Display Filter Bar** at the top of Wireshark.

Example:

```
http
```

Press **Enter** to apply the filter.

---

# Apply as Filter

If you don't remember filter syntax, Wireshark can create filters automatically.

Simply:

1. Click any field in the Packet Details Pane.
2. Right-click.
3. Select **Apply as Filter**.

Wireshark generates and applies the filter for you.

### Example

Right-click:

```
Source IP: 192.168.1.10
```

Wireshark automatically creates:

```
ip.src == 192.168.1.10
```

---

# Conversation Filter

Sometimes you don't want to filter a single field—you want to view **all packets belonging to the same communication**.

A Conversation Filter automatically filters packets using:

- Source IP
- Destination IP
- Source Port
- Destination Port

This allows you to focus on an entire conversation between two devices.

### Use Cases

- Follow a TCP connection
- Investigate suspicious communication
- Analyze client-server interactions

---

# Colourise Conversation

Instead of hiding other packets, Wireshark can simply highlight packets belonging to the same conversation.

This makes related traffic easy to identify while keeping the full capture visible.

### Benefits

- No packets are hidden
- Easy visual tracking
- Useful when comparing multiple conversations

The color can be reset at any time.

---

# Prepare as Filter

This feature is similar to **Apply as Filter**, but it does **not** immediately activate the filter.

Instead, Wireshark places the filter into the Display Filter Bar, allowing you to edit or combine it before applying.

Example:

```
ip.addr == 192.168.1.10
```

You can then extend it:

```
ip.addr == 192.168.1.10 && tcp.port == 80
```

This is useful for building complex filters.

---

# Apply as Column

The Packet List Pane normally shows only basic information.

You can add any field as a new column.

### Example

Right-click:

```
TCP Window Size
```

Choose:

```
Apply as Column
```

A new column is added to every packet showing that field.

### Benefits

- Compare values across packets
- Quickly identify patterns
- Customize the packet list

---

# Follow Stream

Network applications send data across multiple packets.

**Follow Stream** reconstructs those packets into the original conversation.

Supported streams include:

- TCP Stream
- UDP Stream
- HTTP Stream

### Menu

```
Analyze → Follow TCP Stream
```

---

## What Follow Stream Shows

Instead of individual packets, Wireshark displays the complete conversation.

Example:

```
GET /login HTTP/1.1

Username=admin
Password=password123
```

Client data is typically shown in **red**, while server responses appear in **blue**.

This feature is extremely useful for reconstructing application-level communication.

---

## After Following a Stream

Wireshark automatically creates and applies a display filter for that stream.

To return to all packets:

Click the **X** next to the Display Filter Bar.

# Basic Display Filter Syntax

## Filter by Protocol

Show only packets of a specific protocol.

Example:

```
http
```

Other examples:

```
dns
ftp
smtp
imap
pop
arp
dhcp
tcp
udp
icmp
```

---

## Filter by TCP Port

Syntax:

```
tcp.port == <port_number>
```

Examples:

HTTP

```
tcp.port == 80
```

HTTPS

```
tcp.port == 443
```

SSH

```
tcp.port == 22
```

FTP

```
tcp.port == 21
```

---

## Filter by UDP Port

Syntax:

```
udp.port == <port_number>
```

Examples:

DNS

```
udp.port == 53
```

DHCP

```
udp.port == 67
```

---

# Filter by IP Address

Syntax:

```
ip.addr == <IP_Address>
```

Example:

```
ip.addr == 192.168.1.2
```

This displays packets where the IP address appears as either the source or destination.

---

# Common Display Filters

| Filter | Purpose |
|---------|---------|
| `http` | Show HTTP packets |
| `dns` | Show DNS packets |
| `tcp` | Show TCP packets |
| `udp` | Show UDP packets |
| `icmp` | Show ICMP packets |
| `arp` | Show ARP packets |
| `tcp.port == 80` | Show HTTP traffic |
| `tcp.port == 443` | Show HTTPS traffic |
| `udp.port == 53` | Show DNS traffic |
| `ip.addr == 192.168.1.2` | Show packets involving a specific IP |

# Why Packet Filtering is Important

Packet filtering helps analysts:

- Remove unnecessary traffic
- Focus on suspicious packets
- Investigate attacks faster
- Analyze specific devices
- Examine individual conversations
- Reconstruct application traffic
- Reduce investigation time

# Interview Tips

- **Capture Filters** work **before** capturing traffic, while **Display Filters** work **after** the packets are captured.
- Display filters **do not delete packets**; they only hide non-matching packets.
- **Follow Stream** reconstructs application-level communication from multiple packets.
- **Apply as Filter** creates and immediately applies a display filter, whereas **Prepare as Filter** creates the filter but lets you edit it before applying.
- `ip.addr == 192.168.1.2` filters packets where the specified IP is either the **source** or **destination**.
- `tcp.port == 80` filters HTTP traffic based on the TCP port number.
