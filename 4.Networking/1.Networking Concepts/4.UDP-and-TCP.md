# UDP and TCP

## Why Do We Need UDP and TCP?

The **IP protocol** can deliver data to the correct **device (host)** using its IP address.

However, a computer can run many applications at the same time, such as:

- Web Browser
- Email Client
- Discord
- SSH
- FTP

So, after reaching the correct device, we still need a way to deliver the data to the **correct application (process)**.

This is the job of the **Transport Layer (Layer 4)** using:

- **UDP (User Datagram Protocol)**
- **TCP (Transmission Control Protocol)**

---

# Port Numbers

A **port number** identifies a specific application or service running on a computer.

- Uses **2 bytes (16 bits)**
- Range:

```
1 - 65535
```

> **Port 0** is reserved.

### Examples

| Application | Port |
|-------------|------|
| HTTP | 80 |
| HTTPS | 443 |
| SSH | 22 |
| FTP | 21 |
| DNS | 53 |

Think of it like this:

- **IP Address** = House Address 🏠
- **Port Number** = Room Number 🚪

The IP gets the packet to the correct house, and the port gets it to the correct room.

---

# UDP (User Datagram Protocol)

UDP is a **connectionless** transport protocol.

This means:

- No connection is created before sending data.
- Data is sent immediately.
- No guarantee that the receiver gets it.
- No acknowledgement (ACK).
- No retransmission if data is lost.

---

## Characteristics of UDP

- Fast
- Lightweight
- Low overhead
- No reliability
- No packet ordering
- No error recovery

---

## Real-Life Example

Imagine sending a letter through **normal postal mail**.

You simply send it.

You don't know:

- if it arrived
- when it arrived
- whether it was lost

UDP works exactly like this.

---

## Advantages of UDP

- Very fast
- Uses less bandwidth
- Low latency
- Good for real-time communication

---

## Disadvantages of UDP

- No delivery confirmation
- Packets may be lost
- Packets may arrive out of order
- No retransmission

---

## Common Uses of UDP

- Video Streaming
- Voice Calls (VoIP)
- Online Gaming
- DNS
- Live Broadcasts

These applications care more about **speed** than **perfect accuracy**.

---

# TCP (Transmission Control Protocol)

TCP is a **connection-oriented** protocol.

This means:

- A connection must be established first.
- Data is delivered reliably.
- Lost packets are resent.
- Packets arrive in the correct order.
- Receiver confirms every packet.

---

## Characteristics of TCP

- Reliable
- Connection-oriented
- Error checking
- Packet ordering
- Retransmission
- Acknowledgements (ACK)

---

## Real-Life Example

Imagine sending a package through a courier service with **delivery confirmation**.

You receive confirmation when the package arrives.

If something goes wrong, it can be sent again.

That's exactly how TCP works.

---

## Advantages of TCP

- Reliable communication
- Guaranteed delivery
- Correct packet order
- Error detection
- Lost packets are retransmitted

---

## Disadvantages of TCP

- Slower than UDP
- More overhead
- Requires connection setup

---

# Sequence Numbers

Every byte of data sent by TCP has a **Sequence Number**.

This helps the receiver:

- Detect missing packets
- Detect duplicate packets
- Arrange packets in the correct order

---

# Acknowledgement (ACK)

When the receiver gets data successfully, it sends back an:

```
ACK (Acknowledgement)
```

This tells the sender:

> "I received your data successfully."

If an ACK is not received, TCP sends the data again.

---

# TCP Three-Way Handshake

Before sending any data, TCP creates a connection using the **Three-Way Handshake**.

It involves **3 packets**.

---

## Step 1: SYN

The client wants to connect.

It sends:

```
SYN
```

Meaning:

> "Can we communicate?"

---

## Step 2: SYN-ACK

The server replies with:

```
SYN + ACK
```

Meaning:

> "Yes, I received your request, and I'm ready."

---

## Step 3: ACK

The client sends:

```
ACK
```

Meaning:

> "Great! Connection established."

Now both devices can exchange data.

---

## Three-Way Handshake Diagram

```text
Client                        Server

  SYN  --------------------->

       <------------------ SYN + ACK

  ACK  --------------------->
```

After this:

```
Connection Established
```

# UDP vs TCP

| Feature | UDP | TCP |
|---------|-----|-----|
| Full Name | User Datagram Protocol | Transmission Control Protocol |
| Layer | Transport (Layer 4) | Transport (Layer 4) |
| Connection | Connectionless | Connection-Oriented |
| Speed | Fast | Slower |
| Reliability | No | Yes |
| ACK | No | Yes |
| Packet Ordering | No | Yes |
| Retransmission | No | Yes |
| Error Recovery | No | Yes |
| Overhead | Low | High |

---

# When to Use UDP

Use UDP when:

- Speed is more important than reliability.

Examples:

- Online games
- Live streaming
- Voice calls
- Video calls
- DNS

---

# When to Use TCP

Use TCP when:

- Data must arrive correctly.

Examples:

- Web browsing (HTTP/HTTPS)
- Email
- File transfer
- SSH
- Banking
- Online shopping

---

# Important Facts

✅ IP identifies the **device**.

✅ Port identifies the **application**.

✅ UDP is **fast but unreliable**.

✅ TCP is **slower but reliable**.

✅ Both UDP and TCP operate at **OSI Layer 4 (Transport Layer)**.

✅ Port numbers range from:

```
1 - 65535
```
