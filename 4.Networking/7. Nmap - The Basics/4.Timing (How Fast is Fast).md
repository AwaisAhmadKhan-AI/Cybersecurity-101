# Timing (How Fast is Fast?)

Nmap allows you to control **how fast or slow** a scan runs.

This is useful because:

- A **fast scan** finishes quickly but is easier to detect.
- A **slow scan** generates less suspicious traffic and may avoid detection by IDS/IPS or firewalls.

---

# Timing Templates (`-T`)

Nmap provides **6 predefined timing templates**, ranging from very slow to extremely fast.

| Template | Number | Description |
|----------|--------|-------------|
| Paranoid | `-T0` | Slowest scan, designed to avoid detection |
| Sneaky | `-T1` | Very slow scan |
| Polite | `-T2` | Slower scan that reduces network load |
| Normal | `-T3` | Default scan speed |
| Aggressive | `-T4` | Faster scan (commonly used) |
| Insane | `-T5` | Fastest scan, generates heavy traffic |

---

## Syntax

```bash
nmap -T<0-5> <target>
```

or

```bash
nmap -T aggressive <target>
```

---

## Examples

```bash
# Very slow scan
nmap -T0 192.168.1.10

# Default timing
nmap -T3 192.168.1.10

# Faster scan
nmap -T4 192.168.1.10

# Fastest scan
nmap -T5 192.168.1.10
```

# Parallel Probes

Nmap can scan multiple ports **simultaneously**.

You can control the minimum and maximum number of probes sent at the same time.

## Options

```bash
--min-parallelism <number>
```

```bash
--max-parallelism <number>
```

### Example

```bash
nmap --min-parallelism 10 192.168.1.10
```

This ensures Nmap sends **at least 10 probes simultaneously**.

> By default, Nmap automatically adjusts the number of parallel probes based on network conditions.

---

# Packet Rate

You can control **how many packets Nmap sends per second**.

## Options

```bash
--min-rate <number>
```

```bash
--max-rate <number>
```

### Example

```bash
nmap --min-rate 500 192.168.1.10
```

This tells Nmap to send **at least 500 packets per second**.

> The specified rate applies to the **entire scan**, not to each individual host.

---

# Host Timeout

Some hosts respond very slowly.

Instead of waiting indefinitely, you can specify the maximum amount of time Nmap should spend scanning a host.

## Syntax

```bash
--host-timeout <time>
```

### Example

```bash
nmap --host-timeout 2m 192.168.1.10
```

If the scan takes longer than **2 minutes**, Nmap stops scanning that host.

---

# Summary

| Option | Description |
|---------|-------------|
| `-T0` | Paranoid (slowest) |
| `-T1` | Sneaky |
| `-T2` | Polite |
| `-T3` | Normal (default) |
| `-T4` | Aggressive |
| `-T5` | Insane (fastest) |
| `--min-parallelism <num>` | Minimum number of parallel probes |
| `--max-parallelism <num>` | Maximum number of parallel probes |
| `--min-rate <num>` | Minimum packets sent per second |
| `--max-rate <num>` | Maximum packets sent per second |
| `--host-timeout <time>` | Maximum time to wait for a host |

---

# Common Examples

```bash
# Default scan
nmap -T3 192.168.1.10

# Aggressive scan
nmap -T4 192.168.1.10

# Slow stealthy scan
nmap -T1 192.168.1.10

# Set minimum packet rate
nmap --min-rate 500 192.168.1.10

# Set host timeout
nmap --host-timeout 2m 192.168.1.10

# Fast scan with aggressive timing
nmap -sS -F -T4 192.168.1.10
```
