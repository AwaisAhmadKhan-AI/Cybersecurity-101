# ARP (Address Resolution Protocol)

## Overview

* ARP = Address Resolution Protocol
* Used to translate:

  * IP Address (Layer 3)
  * → MAC Address (Layer 2)

* Essential for communication on:

  * Ethernet (IEEE 802.3)
  * WiFi (IEEE 802.11)

---

# Why ARP is Important

When two hosts communicate on the same local network:

* Devices use IP addresses to identify each other
* Ethernet/WiFi communication requires MAC addresses

Even if a device knows the target IP address, it still needs the target MAC address to create the Ethernet frame.

---

# Layer 2 and Layer 3 Relationship

## Layer 3

Handles:

* IP Addressing
* Routing
* Logical communication

Example:

```text
192.168.66.1
```

---

## Layer 2

Handles:

* MAC Addressing
* Physical network communication

Example:

```text
44:DF:65:D8:FE:6C
```

---

# MAC Address

## Overview

* MAC Address = unique hardware identifier
* 48-bit hexadecimal value

Examples:

```text
7C:DF:A1:D3:8C:5C
44:DF:65:D8:FE:6C
```

---

# Ethernet Frame

An IP packet is encapsulated inside an Ethernet frame.

Ethernet header contains:

* Destination MAC Address
* Source MAC Address
* Protocol Type

Example:

```text
Destination MAC → ff:ff:ff:ff:ff:ff
Source MAC      → cc:5e:f8:02:21:a7
Type            → IPv4
```

---

# Problem ARP Solves

Devices normally know:

* IP address of gateway
* IP address of DNS server
* IP address of target system

But they do NOT automatically know:

* MAC address of target device

Without the MAC address, Ethernet communication cannot happen.

---

# How ARP Works

Suppose:

```text
Sender IP → 192.168.66.89
Target IP → 192.168.66.1
```

The sender wants to communicate with the target but does not know its MAC address.

ARP process:

1. Send ARP Request
2. Receive ARP Reply
3. Start communication

---

# ARP Request

The sender broadcasts a request:

```text
Who has 192.168.66.1?
Tell 192.168.66.89
```

Characteristics:

* Sent to broadcast MAC address:

```text
ff:ff:ff:ff:ff:ff
```

* Every device on local network receives it
* Only the correct device replies

---

# ARP Reply

The target device responds:

```text
192.168.66.1 is at 44:df:65:d8:fe:6c
```

This provides:

* Target MAC address
* Ability to start direct communication

---

# ARP Packet Example Using tshark

Command:

```bash
tshark -r arp.pcapng -Nn
```

Output:

```text
1 0.000000000 cc:5e:f8:02:21:a7 → ff:ff:ff:ff:ff:ff ARP 42 Who has 192.168.66.1? Tell 192.168.66.89

2 0.003566632 44:df:65:d8:fe:6c → cc:5e:f8:02:21:a7 ARP 42 192.168.66.1 is at 44:df:65:d8:fe:6c
```

---

# ARP Packet Example Using tcpdump

Command:

```bash
tcpdump -r arp.pcapng -n -v
```

Output:

```text
ARP Request who-has 192.168.66.1 tell 192.168.66.89

ARP Reply 192.168.66.1 is-at 44:df:65:d8:fe:6c
```

---

# Important Observations

## ARP Uses Broadcast

ARP Request is sent using:

```text
ff:ff:ff:ff:ff:ff
```

because the sender does not know the target MAC address yet.

---

## ARP Reply is Unicast

The ARP Reply is sent directly back to the requester.

---

# Encapsulation

ARP packets are:

* NOT encapsulated inside:

  * TCP
  * UDP
  * IP

* ARP is encapsulated directly inside Ethernet frames.

---

# ARP and OSI Model

ARP is generally considered:

* Layer 2 protocol

because it works with MAC addresses.

Some also associate it with Layer 3 because it supports IP communication.

Main purpose:

```text
Layer 3 IP Address
        ↓
Layer 2 MAC Address
```

---

# Real-World Communication Flow

Example process:

1. Device gets IP configuration using DHCP
2. Device learns:

   * Gateway IP
   * DNS IP

3. Before sending traffic:

   * Device performs ARP lookup
   * Obtains target MAC address

4. Ethernet communication begins

---

# Key Points

* ARP translates IP addresses into MAC addresses
* Required for local network communication
* Works on Ethernet and WiFi
* Uses:

  * ARP Request
  * ARP Reply

* ARP Request uses broadcast MAC
* ARP Reply provides target MAC address
* ARP packets are directly encapsulated inside Ethernet frames
* Bridges Layer 3 addressing to Layer 2 addressing
