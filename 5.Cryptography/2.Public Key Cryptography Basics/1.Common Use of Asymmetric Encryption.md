# Common Use of Asymmetric Encryption

## Why Do We Need Asymmetric Encryption?

Asymmetric encryption is **slower** than symmetric encryption.

Instead of encrypting all communication with asymmetric encryption, it is mainly used to **securely exchange the symmetric encryption key**.

Once both parties have the same symmetric key, they switch to **faster symmetric encryption** for the rest of the communication.

---

# The Problem

Suppose you want to communicate securely with a server.

To use symmetric encryption, both you and the server must have the **same secret key**.

But:

**How do you send the secret key without an attacker seeing it?**

This is where **asymmetric encryption** solves the problem.

---

# Lock and Box Analogy

Imagine you want to send secret instructions to your friend.

Instead of sending them openly, you ask your friend for a **lock**.

Only your friend has the **key** that can open this lock.

### Step 1

Your friend sends you their **lock**.

```
Friend
   │
   ▼
 Public Lock
```

---

### Step 2

You place the secret instructions inside an indestructible box.

```
Secret Instructions
        │
        ▼
     Put in Box
```

---

### Step 3

You lock the box using your friend's lock.

```
Secret Instructions
        │
        ▼
 Locked Box
```

---

### Step 4

You send the locked box to your friend.

Even if someone intercepts it, they **cannot open it**.

---

### Step 5

Your friend uses their **private key** (the only key that fits the lock) to open the box and read the instructions.

---

```

        Public Key
<-------------------------------

Encrypt Symmetric Key

        │
        ▼

                 Decrypt using
                 Private Key
                        │

═══════════════════════════════════════

Now both use:

Symmetric Encryption
(Fast & Efficient)
```

# Why Use Both Types?

## Step 1

Use **asymmetric encryption** once.

Purpose:

- Securely exchange the symmetric key.

---

## Step 2

Use **symmetric encryption** for all future communication.

Reason:

- Much faster.
- Less computationally expensive.

---

# Real-World Example

When you visit a secure website (**HTTPS**):

1. Your browser receives the server's **public key**.
2. Your browser encrypts a **symmetric session key** using that public key.
3. The server decrypts it using its **private key**.
4. Both sides now share the same secret key.
5. All remaining communication is encrypted using **symmetric encryption**.

---

# Note

In the real world, exchanging keys alone is **not enough**.

You also need to verify that the server is really who it claims to be.

This is done using:

- **Digital Signatures**
- **Digital Certificates**

These help prevent attackers from pretending to be legitimate servers.

---

# Summary

- Asymmetric encryption is mainly used to **securely exchange symmetric keys**.
- It solves the problem of sending a secret key over an insecure network.
- The **public key** encrypts the symmetric key.
- The **private key** decrypts the symmetric key.
- After the key exchange, communication switches to **fast symmetric encryption**.
- In real-world systems, **digital signatures** and **certificates** are used to verify identities.

---

# Quick Recap

- **Asymmetric encryption** is slow but excellent for **key exchange**.
- **Symmetric encryption** is fast and used for ongoing communication.
- **Public Key** → Used to encrypt.
- **Private Key** → Used to decrypt.
- Real systems also use **digital signatures** and **certificates** to verify identities.
