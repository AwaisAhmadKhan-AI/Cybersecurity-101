# Diffie-Hellman Key Exchange

## What Problem Does Diffie-Hellman Solve?

One major problem with **symmetric encryption** is **sharing the secret key**.

### Example

Suppose you want to send a **password-protected document** to your business partner.

- You can email the encrypted file.
- But how do you safely send the password?
- If you email the password too, an attacker can steal both.

**Diffie-Hellman Key Exchange (DHKE)** solves this problem by allowing two people to create the **same secret key** over an insecure network **without ever sending the secret key itself**.

---

# What is Diffie-Hellman Key Exchange?

**Diffie-Hellman Key Exchange (DHKE)** is a method that allows two parties to:

- Create a shared secret key
- Communicate over an insecure network
- Never transmit the secret key directly
- Use the shared key later for **symmetric encryption** (such as AES)

> **Important:** Diffie-Hellman does **not** encrypt data itself. It only creates a shared secret key.

---

# Simple Idea

Imagine Alice and Bob want to communicate securely.

Each person:

- Creates a private secret.
- Exchanges only public information.
- Uses their own secret together with the received public information.
- Both end up with the **same secret key**.

Even if someone watches the communication, they cannot calculate the secret key.

---

# Step-by-Step Process

## Step 1: Agree on Public Values

Alice and Bob publicly agree on two numbers:

- Prime number **p**
- Generator **g**

Example:

```
p = 29
g = 3
```

These numbers are **public** and everyone can know them.

---

## Step 2: Choose Private Keys

Each person secretly chooses a number.

Alice:

```
a = 13
```

Bob:

```
b = 15
```

These values are **private** and must never be shared.

---

## Step 3: Generate Public Keys

Each person calculates a public key.

### Alice

```
A = gᵃ mod p

A = 3¹³ mod 29 = 19
```

### Bob

```
B = gᵇ mod p

B = 3¹⁵ mod 29 = 26
```

Their public keys are:

```
Alice → 19
Bob → 26
```

---

## Step 4: Exchange Public Keys

They exchange only the public keys.

Alice sends:

```
19
```

Bob sends:

```
26
```

Anyone can see these numbers.

---

## Step 5: Calculate the Shared Secret

### Alice calculates

```
Shared Secret = Bᵃ mod p

= 26¹³ mod 29

= 10
```

### Bob calculates

```
Shared Secret = Aᵇ mod p

= 19¹⁵ mod 29

= 10
```

Both get:

```
Shared Secret = 10
```

Neither Alice nor Bob ever sent **10** across the network.

---

# Why Does It Work?

Alice computes:

```
(gᵇ)ᵃ mod p
```

Bob computes:

```
(gᵃ)ᵇ mod p
```

Because

```
(gᵇ)ᵃ = gᵃᵇ

(gᵃ)ᵇ = gᵃᵇ
```

Both calculations produce the **same result**, so both users obtain the same shared secret.

---

# Why is it Secure?

An attacker can see:

- p
- g
- Alice's public key
- Bob's public key

But they **cannot determine Alice's or Bob's private keys**.

Without the private keys, calculating the shared secret is **practically infeasible** when very large numbers are used.

> The example numbers are intentionally small for learning. Real systems use much larger values.

---

# Diffie-Hellman and RSA Together

Diffie-Hellman is often used together with **RSA**.

### Diffie-Hellman

- Creates a shared secret key
- Used for key agreement

### RSA

- Verifies identity
- Provides authentication
- Creates digital signatures
- Helps prevent Man-in-the-Middle (MITM) attacks
- Can securely transport keys

Together they provide a complete security solution.

# Key Terms

| Term | Meaning |
|-------|---------|
| **p** | Public prime number |
| **g** | Public generator |
| **a** | Alice's private key |
| **b** | Bob's private key |
| **A = gᵃ mod p** | Alice's public key |
| **B = gᵇ mod p** | Bob's public key |
| **Shared Secret** | Final secret key used for symmetric encryption |

---

# Quick Summary

- Diffie-Hellman solves the **key-sharing problem**.
- It allows two people to create the **same secret key** over an insecure network.
- The secret key is **never transmitted**.
- Only **public values** are exchanged.
- The shared secret is later used for **symmetric encryption**.
- Diffie-Hellman is commonly used alongside **RSA** for authentication and secure communication.
